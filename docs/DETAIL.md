# 会话标题编号格式

这个插件接管 DSH 自动生成的会话标题，把它们改成固定形状：

```
3-[cdc]测试kafkachangefeed
```

它替换掉内置的自由标题提供方（`@deepseek-ai/dsh-session-title-all-prompts-llm`），每当你在某个会话里发一条新消息，就用当前会话的模型重新生成一次标题。

## 标题形状

- **编号**：一个整数加一个连字符，例如 `3-`。编号由插件决定，模型改写无效。
- **组件**：恰好一个方括号，里面是仓库、产品组件或功能名，例如 `clinic`、`cdc`、`premium`、`essential`、`集成`。由模型按对话内容挑，只用一到三个词、最多 24 个字符；多写的方括号会被去掉。
- **任务**：方括号后面紧跟当前在做的事，用对话的语言，目标约 6 个英文单词或 14 个汉字。

模型如果忘了方括号，任务部分会保留、组件补成 `[其他]`；如果它自己编了编号，以插件给的编号为准；如果有代码块、引号、星号、多余换行，会先清理再拼装。最终标题不超过服务端的 120 字节上限。

## 编号规则

- 编号是**本工作区里第几个开始生成标题的会话**：第一个得到标题的会话是 `1`，之后依次 `2`、`3`……，一个会话只拿一次号，之后改名、改主题、重启都不变。
- 号不会被回收：删掉会话后，新会话继续往后排，不会把旧号让给别人。所以同时存在的会话不会重号，但号可能不连续。
- 编号按会话的 `cwd`（工作区）分开计算，不同项目各自从 `1` 开始。
- 子代理会话不占编号，标题只写 `[组件]任务`。

## 什么时候变

- 你每发一条消息，插件都会重新判断。如果当前标题仍然准确，模型会原样返回（提示词要求如此）；只有主题真的变了才换。
- 已经存在的旧会话不会批量改标题，等你在那个会话里发下一条消息时才会换成新格式，并按当时顺序拿号。

## 配置与状态

- 长度目标、超时、输入上限都在 `cordis.patch.yml` 的对应配置里：`targetWords`、`targetCjkCharacters`、`maxInputBytes`、`maxOutputTokens`、`timeoutMs`。改完需要重新加载插件（修改已安装插件的配置后重启 DSH 最稳）。
- 没有单独配置模型：标题请求跟随当前会话的模型路由（和内置提供方一样）。
- 编号注册表：`~/.local/state/dsh-session-title-format/numbers.json`。删掉它等于从 `1` 重新发号；已经写进标题里的旧编号不会回改，可能因此出现重号。文件损坏时会自动改名成 `.corrupt-<时间戳>` 并重新开始，不会让标题生成失败。

## 已验证与未验证

- 单元测试覆盖：编号改写、占位组件、多余方括号、代码块/引号/星号清理、子代理不编号、120 字节截断、编号冻结与重启保持、损坏注册表恢复、流式文本拼装、失败结束码、配置校验，以及用假 ctx 走通一遍 provider 注册与标题生成。`node --test test/*.test.js` 共 22 项通过。
- 真实环境已验证：一次子代理会话成功生成了 `[组件]任务` 形式的标题（无编号，符合子代理规则），请求走了会话自己的路由。
- 未验证：顶层会话带编号的标题还没在真实界面里出现过，需要你发一条消息后看左侧标题。
